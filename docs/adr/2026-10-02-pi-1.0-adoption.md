# Pi 1.0 launch forms, codemode and Durable adoption

- Status: accepted
- Date: 2026-10-02

## Context

Pi 1.0 makes fullscreen the default and leaves print mode, model selection, tool
allowlists and stdin handling unchanged. The reviewed launch form must keep the
reviewer's input bounded while preserving the worktree context required by foremen
and implementers. The research, Sol/Luna codemode A/B and Gemini reliability test,
and Durable prototype establish the adoption limits below.

PR #540 ships the built-in MCP exposure keys and `autoEnableCodemode: false`,
`settings.extensions: ["-builtin:mcp"]` and the TypeBox peer patch. Its move of the
default model to meta Muse 1.3 was dropped on 2026-10-03, when every Muse route failed
a probe; the default model is a separate owner-gated follow-up. This ADR records the
remaining decisions; it does not repeat those edits.

All experiments ran on synthetic/public data in scratch clones only. Codemode
`models.classify()` and image calls must never receive non-public data.

## Decision

### Reviewer and foreman launch policy

Owner hard rule: all delegated agent work (workers, reviewers, consults, foremen,
research, and one-shot `pi -p`/`codex exec`) runs in a visible Herdr pane. Only
harness-native subagents (Claude Code Agent tool, in-process Plan subagents) and
Dynamic Workflow agents are exempt; no model CLI runs in a background shell,
`nohup`, orphaned process, or supervisor script.

A context-free reviewer bundle therefore runs as this print command inside a
visible pane (the split/run/wait/close form is in the herdr-foreman reference
linked below):

```sh
pi -p --model <provider/model:effort> --no-tools --no-approve -nc "$(cat bundle.md)" < /dev/null | tee out.md
```

- `-p` runs a one-shot print request; `--model` pins its provider, model and effort.
- `--no-tools` empties the registry, preventing MCP or codemode from re-enabling tools.
- `--no-approve` skips cwd project `.pi/` resources; the global
  `defaultProjectTrust` is `always`. This is not a sandbox: user-level extensions
  still load.
- `-nc` turns off `AGENTS.md`/`CLAUDE.md` discovery, which is independent of project
  trust, so repository instructions stay out of the review. User-level extensions
  and skills can still add context.
- `< /dev/null` supplies EOF: print mode reads non-TTY stdin through EOF with no
  timeout. `tee out.md` captures the final answer and keeps it visible in the pane.

Foremen and implementers never pass `-nc`/`--no-context-files` or `--no-rules`;
they must ingest the worktree's CLAUDE.md/Trellis layer. Automated runs state the
project-trust decision explicitly: use `--no-approve` or state that the worktree's
project resources are intended. Never silently add `--approve`. The fullscreen TUI
is the Pi 1.0 default; `herdr pane read --source visible` reads it (verified
2026-10-02), so `--tui-mode regular` is unnecessary. The operational form is in
[herdr-foreman launch guidance](../../core-rules/references/herdr-foreman.md#pi-launch-forms-110-and-above).

### Codemode and Gemini

Codemode is not a default for any role. Enable it only for a unit that benefits
from script batching, with an explicit `--tools …,codemode` allowlist; Sol
multi-file batch edits are the best fit. The A/B used nine cells per model and
condition, and every cell passed:

| Measure | Sol control | Sol codemode | Luna control | Luna codemode |
|---|---:|---:|---:|---:|
| Pass | 9/9 | 9/9 | 9/9 | 9/9 |
| NC tokens | 163,273 | 147,938 | 147,427 | 134,307 |
| All tokens | 414,793 | 432,482 | 482,275 | 488,099 |
| Nested calls | 0 | 44 | 0 | 0 |

The research pilot bar was a token drop of 20% or more, or a wall-time drop.
Sol met neither. Luna's Pi wall sum fell 2.4%, which meets the bar's letter, but
Luna never invoked codemode, so the drop is not a codemode benefit. Sol's NC
changed by -9.39%, all-category tokens by +4.26%, reported cost by -4.48%, and Pi
wall time by +8.38%. Sol's U1 multi-file edit reduced all tokens by 7.04% and cost
by 12.97%; U3 search increased all tokens by 52.58%. NC is reported noncached
input plus output; all tokens include cached input. Sol invoked codemode in 8/9
enabled cells, while Luna invoked it in 0/9. Reported costs are usage metadata,
not independently verified invoices. The results support selective trials, not a
default.

Gemini 3.8 Flash under pi-antigravity 0.7.0 returned `MALFORMED_FUNCTION_CALL` in
20/20 runs in both codemode-only and control, and codemode did not improve the
failure. After pi-antigravity 0.9.0 was installed (2026-10-03, about 03:30 IST), the
same synthetic fixture (read/grep/find/ls questions; 4 questions × 2 repetitions × both
arms) ran 16/16 correct, with tool calls in every run and no malformed calls. Panes
started after that install may give Gemini tools of that shape; panes started earlier
still run 0.7.0 and stay `--no-tools` until restarted. Other tool shapes need their own
probe, and this fixture is re-run after any pi-antigravity upgrade. After
any Pi or pi-mcp-adapter upgrade, re-probe with both `pi mcp list` and `/mcp` in one
live session.

### Pi Durable

The prototype passed two `kill -9` / resume cycles, produced three side effects
without duplicates, and reconciled recorded usage. It is not adopted as the
herdr-foreman driver. The API is experimental; the prototype loads no extensions,
so it lacks Muse/Gemini providers and pi-subagents; and spend for a request killed
mid-generation is not reconciled. Keep Durable as an opt-in pilot, not the
production driver.

## Consequences

Reviewer runs get no tools and no repository context files, while foremen
and implementers retain required worktree context. Automated invocations must make
the project-trust choice visible. Codemode remains a per-unit option with an
explicit allowlist; Gemini tool use is verified only on pi-antigravity 0.9.0. Durable's successful crash-resume
prototype does not qualify it to replace the extension-enabled herdr-foreman path.
