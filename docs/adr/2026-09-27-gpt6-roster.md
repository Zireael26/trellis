# The herdr-foreman roster moves to GPT-6; Terra is retired; verdict independence is per role

- Status: accepted
- Date: 2026-09-27

## Context

The operator ordered every GPT-5.6 model replaced by its GPT-6 equivalent and
GPT-5.6 Terra retired with no replacement (roster directive, 2026-09-27). The
same directive set the routing policy:

- Claude Opus 5.5 at medium/high carries the majority of reasoning work
  (design, non-trivial implementation, integration) and reviews OpenAI output.
- GPT-6 Sol at high..max is the workhorse for well-specified coding and for
  reviews of Claude, Muse or Gemini output.
- GPT-6 Luna runs at max only, for cheap bounded work.
- GPT-6 Astra (medium or high, never above) takes only the hardest units.
- Gemini 3.8 Flash and Muse Spark take scans, first-pass reviews and refuter
  seats; Grok takes security review and refuter seats while it has credits.

The directive also required fixing two permanent SessionStart degradations:
`merge_reviewer` had no candidate, and the refuter had 1 of 3 seats. Neither
was a quota problem. The resolver required every verdict role (reviewer,
security reviewer, merge reviewer, and three refuter seats) to be in a family
distinct from the implementer **and from every other verdict role**. Beside an
OpenAI implementer that needs six other families; the roster has three (Meta,
Google, xAI), four once Claude joins. The rule could never be satisfied for the
default implementer, so the roster showed DEGRADED in every session, and a
check that is always red stops being read.

## Decision

1. **Roster.** Catalog agents `sol` (gpt-6-sol:high), `sol-xhigh` (foreman seat
   and first hard rung), `sol-max` (exact operator selection only), `luna`
   (gpt-6-luna:max), and `astra` (gpt-6-astra:high, `hard-work` only). Terra
   and every gpt-5.6 id leave the live roster, pi agent definitions, recipes,
   and live docs. Historical records are not rewritten.
2. **Claude joins the catalog as a verdict seat.** `opus`
   (`anthropic/claude-opus-5-5:high`, family `anthropic`, harness
   `claude-code`) can hold `security-review` and `merge-review`. It is
   dispatched through Claude Code, never on pi, and is in no non-verdict chain:
   Claude implementation work is the apex's choice under `claude_roles`, not a
   resolver route. The OpenUsage adapter now maps the `claude` report to
   provider `anthropic` so that seat obeys real quota instead of being dropped.
3. **Verdict independence is per role (spec 052, option C′).** Exactly three
   rules replace all-roles-distinct:
   1. every verdict seat (reviewer, security reviewer, merge reviewer, each
      refuter seat) differs from the producer's family;
   2. the security reviewer differs from the reviewer's family, the second
      opinion;
   3. the three refuter seats are pairwise distinct, and each differs from the
      reviewer's family.

   The merge reviewer may share any verdict family; a refuter seat may share
   the security or merge reviewer's family. Roles resolve in a fixed order
   (non-verdict roles, then reviewer, security reviewer, merge reviewer,
   refuter), so the rule does not depend on key order in `roles.json`. The
   resolver (`family_collapse`), both SessionStart hook copies and
   `hooks/lib/code-reviewer.sh` enforce the same rules against one crafted
   fixture set. The first draft let refuters share the reviewer's family; all
   four round-1 reviewers rejected it, because on the healthy roster Muse was
   both the first-pass reviewer and refuter seat 0, so N-of-3 was two
   independent votes plus an echo of the finding's author.
4. **Refuter quorum.** A finding is dismissed only when at least 2 refuter
   seats outside the finding author's family vote to refute it. A seat in the
   author's family is recused. `resolve-roles.py --panel a,b,c
   --finding-author <agent>` prints the recused seats and eligible votes and
   exits 1 below 2; without `--finding-author`, `--panel` keeps its
   distinct-family count.
5. **Launcher.** Each catalog agent declares `harness` (`pi` or
   `claude-code`; anything else refuses the catalog). Role rows, trail entries
   and classification receipts carry `launcher: pi | apex`. An `apex` route is
   an instruction to the apex to run a Claude Code subagent or Claude pane at
   `--effort high`. `dispatchable` keeps meaning "eligible" and `runtime_match`
   is unchanged. The foreman, implementer, hard_implementer, deep_worker, scout
   and reviewer chains are pi-only, and `foreman-start.sh` and
   `code-reviewer.sh` start only the foreman and reviewer routes.

With every provider healthy, each catalog implementer resolves without
DEGRADED. An OpenAI implementer gets reviewer `cheap-2` (Meta), security
`security-reviewer` (xAI), merge `opus` (Anthropic), and refuters `gemini`,
`grok` and `opus`. A Claude implementer gets merge `sol-xhigh` and never an
Opus seat. A real outage still degrades loudly: Google exhausted beside an
OpenAI implementer leaves the refuter at 2/3.

## Consequences

- The standing invariant is the operator's: reviewer family ≠ producer family.
  The stricter all-roles-distinct rule is gone. The assurance trade-off: a
  merge verdict may come from the reviewer's family, and a refuter may share
  the security or merge reviewer's family. The quorum recusal covers the
  second case when that reviewer authored the finding.
- The artifact field `verdict_families_distinct` keeps its name so validators
  from the previous release accept new artifacts during rollout. It now means
  "no family collapse and no degraded verdict role".
- A resolved `opus` route is an instruction to the apex to run a Claude
  reviewer, not a pi dispatch.
- Astra and `sol-max` share Codex quota with `sol` and sit in no automatic
  chain. They are exact selections (`--operator-agent`) for the hardest units,
  which matches the directive.

## Activation

The rule change touches validators that are project-attached
(`hooks/lib/code-reviewer.sh`) as well as the user-surface SessionStart hooks,
so the release activates in this order:

1. Install 1.3.6.
2. Adopt by lane window. Checkouts with no active lane are adopted at once;
   for each lane-owned checkout the apex asks the owning lane for a clean
   point (no push, gate run or session start in flight), adopts, and gets the
   lane to confirm. New validators accept old artifacts, so adopting first
   never rejects a valid roster.
3. Configure (`trellis configure --release 1.3.6 --no-install-launcher`)
   only after every active registry row is adopted or reported unavailable.
   It relinks the owned user surface, including both SessionStart hooks, as one
   transition with machine config.
4. Announce `ROSTER LIVE 1.3.6` in the handoff file, so sessions restart or
   re-resolve.

Honest limits, all pre-existing:

- A session whose cached artifact binds the old policy SHA is rejected until
  its next deciding pass regenerates it.
- An old SessionStart hook already running at the instant of configure may
  reject its own output and print DEGRADED for that session start.
- While an artifact is rejected, the Stop reviewer drops to its regex-only
  deterministic rung. That is reduced assurance, not fail-closed review; a
  project that failed adoption stays there until it is adopted. Making the
  Stop review fail closed on a policy mismatch is a follow-up.

Rollback is `trellis configure --release 1.3.4`.
